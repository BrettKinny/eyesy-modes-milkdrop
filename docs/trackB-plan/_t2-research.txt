## Part 4 — Port feasibility to our ES2/Lua platform

**Warp mesh (per-vertex UV displacement).** MilkDrop/projectM compute per-vertex equations on a ~32x24 grid, bilinear-interp across triangles, feed displaced uv to the warp shader. Our fragment's uv is rectilinear with only scalar uniforms injectable — no mesh-to-shader uv channel. Verdict: do NOT port the CPU mesh. Compute displacement analytically per-pixel in the fragment: `uv_w = f(uv_orig, zoom,rot,dx,dy,warp,sphere, cx,cy)` with named float uniforms set from Lua per frame. Strictly richer (no interp, no grid precision loss), removes host cost. The 95% case (zoom/rot/translate + spherical/cylindrical warp + sine flow) is closed-form in-fragment. Only the per-vertex index/sector tricks (e.g. an 8-sector wedge) need rewriting as per-pixel branchless sector equations — which is exactly what the preset's per_pixel block already is, so the rewrite is mechanical.

**Comp shader (HLSL ps_2_0) vs ES2.** Composite is a separate display-only fragment sampling the main canvas. ES2 draw_shader binds up to 6 target samplers — bind the feedback target as a sampler and the whole comp effect class (gamma, glow, edge-detect = abs(crisp-blurry), solarize = 1-ret*(1-ret)*4, overbrighten, soft-max, hue ramp) ports line-for-line. Cosmetic renames: tex2D(sampler_main,uv).xyz -> texture2D(mainSampler,uv).rgb; GetBlur1 -> 2-tap gather; float3 -> vec3; dot/lum/lerp/saturate/pow/sqrt/abs/fract/sin/cos are stock GLSL. ps_2_0-only constructs requiring rework: sampler STATE blocks (-> draw_shader sampler args), texsize_*/aspect.xy pseudo-uniforms (-> named uniforms), float4x3 dynamic-rotation matrices (-> fmt in Lua, pass as floats), half/swizzle sugar (-> float/vec). No blocker.

**Vertex texture fetch (absent in GLES2).** The one hard gap: our mesh vertices carry position only, no per-vertex UV, so textured shapes (textured=1 sampling the previous frame into a polygon) cannot be mesh triangles with per-vertex texture. Workaround: render the shape as a masked fragment (draw the feedback target through a polygon mask in a comp pass) — loses per-polygon UV but preserves the look.

**Texture depths / blur passes.** MilkDrop keeps 3 progressively-blurred Main textures (blur1/2/3). We have 8 targets, 6 samplers/fragment. Options: (a) 1 pass = single fragment sampling the prior target at 4-8 pixel offsets (the blur1_ps.fx 8-tap unfolded; ~4-8 texture taps); (b) blur2/3 = sample the existing half-res feedback buffer upscaled — downsampling is a natural low-pass, giving Blur2/Blur3 for free; (c) dedicate 2 spare targets as separable blur buffers only for rare big-radius needs. Recommend (a)+(b): no extra targets, cheap, matches how kali/phosphor already do feedback.

**Per-frame equations -> Lua; Q-bridging -> uniforms.** The AVS expression pool (persistent custom vars, q1-q32, bass/mid/treb+att, time/fps, if/equal/above/below/rand/min/max/sin/cos/pow) maps to Lua update() plus ctx.audio bands and eyesy.random (deterministic). The MilkDrop pattern — a few persistent custom vars, q-values computed per frame then consumed by shaders — becomes: compute qs in Lua, pass {q1=..., q2=..., c0..c4=...} as the named-uniform table to draw_shader. Identical channel (include.fx feeds q* to shaders as _qa.._qh uniforms).

**Noise/dithering.** No procedural noise sampler on ES2; replace with in-fragment GLSL hash (e.g. `vec2 p=fract(uv*vec2(123.34,456.21)); return fract((p.x+p.y)*p.x*p.y)`) seeded by a uniform — same band-breaking dither as noise_lq + rand_frame.xy.

## Part 5 — Concrete port plan: a single Lua 'milkdrop-engine' mode

Yes — one engine mode can LOAD preset parameter JSONs as variants, because our platform already carries scene state as string-keyed tables in save()/restore(), and variants swap exactly like scene recall.

Layout (modes/milkdrop-engine/):
- main.lua — the engine. setup() builds a library of shader handles + meshes; update(dt) runs the active preset's per-frame expression block and writes q*/uniforms; draw() runs warp->feedback then composite->screen; restore(state) loads a preset JSON and re-seeds q/init; knobs1-5/trigger cycle variants, re-seed morphology (the MilkDrop 'c' randomize-colors = re-seed palette + rot/roam matrices), hard-cut next preset on bass spikes (F8-style).
- presets/<name>.json — variant data: {warp:<fragId>, comp:<fragId>, per_frame:[exprs], per_vertex:[exprs], waves:[{type,points}|{per_point:[exprs]}], shapes:[...], q_init:{}, palette:<name>, uniforms:{c0..c4,q1..q32}, autopreset:{mode,bass_thresh,delay_min}}. One JSON per shipped preset (.milk is ~2-5KB; JSON same order).
- eval.lua — a ~150-line AVS-expression evaluator (parse-on-load, eval per frame) supporting the operator/function subset above, with 3 variable pools + persistence + q1-q32 as in the spec. Makes 'preset = data' true (projectM/Butterchurn do exactly this).
- frag/ — ~30 canonical GLES2 fragments: warp_darken, warp_sphere, warp_flowslug, warp_wedge, warp_fold, comp_passthru, comp_glow, comp_edge, comp_solarize, comp_softmax, comp_plasma, comp_grid, comp_tint, comp_kaleido, blur_gather (8-tap), dither_noise... A preset's per-pixel displacement + comp effect are chosen shaders + uniform values, not transpiled HLSL.

**Perf budget (640x360 half-res feedback, fleet envelope 15.7-30.3ms):** warp fragment @640x360 ~1-2ms; composite (multi-sampler, 5-gather) ~ the kali-bloom ~30ms@10-iter envelope; wave meshes 3x512 = 1536 verts = trivial CPU; aim for the 15.7ms tile on Tier A. Blur taps only in comp (never in the feedback loop) to avoid the in-repo bloom self-amplify trap — the warp/composite split guarantees this by construction.

This is strictly a super-set of the half-res ping-pong + hybrid fragment idiom proven by modes/phosphor and modes/kali-bloom — no new rendering path, only a parameter-typed scene-recognition layer on top.
